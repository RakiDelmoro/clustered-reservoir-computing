**ASSISTANT:** The root cause is clear: the model was trained on fixed-length 60-frame sequences, but during autoregressive inference the aggregation (first, last, mean, max) grows unbounded, shifting the feature distribution away from what the readout was trained on.

## Approaches

### 1. Sliding Window Aggregation (Recommended)

Only aggregate over the **last `seq_length` (60) states**, matching the training distribution exactly. The reservoir state still runs autoregressively (its leaking rate α already provides natural forgetting), but the aggregation window is capped.

```
Frame t=100 → reservoir state accumulated from all frames
            → but only aggregate states[max(0, t-59):t+1] for first/last/mean/max
```

- Pro: Feature distribution matches training, simple change
- Con: Reservoir state still carries full history (though α-forgetting mitigates this)

### 2. Sliding Window + Reservoir Reset

Same as above, but also **reset the reservoir state to zero** at the start of each window. This fully matches training conditions (each training sample starts from zero state).

- Pro: Perfect match to training distribution
- Con: Prediction is "cold" at the start of each window (no context from previous window)

### 3. Sliding Window + State Decay

Between windows, don't reset to zero — instead **scale down** the reservoir state (e.g., multiply by 0.5). Provides a soft reset that retains some context.

- Pro: Balance between clean slate and continuity
- Con: Introduces a new hyperparameter (decay factor)

### My recommendation

**Approach 1** is the best starting point — it's the simplest fix and directly addresses the core problem (unbounded aggregation). The reservoir's built-in α-forgetting already handles the temporal decay of the state itself. If predictions are still too sticky, we can escalate to approach 2 or 3.

The change is small: instead of `state_history.append(state)` growing forever, keep a `deque(maxlen=seq_length)` so old states are automatically dropped.

**ASSISTANT:** ## What Sliding Window Means

At each frame `t`, the model goes through this pipeline:

```
Frame t → SpatialEncoder → embedding → Reservoir(prev_state) → new_state
                                                                ↓
                                       state_window keeps last 60 states
                                                                ↓
                                       Aggregate those 60 states → features → readout → prediction
```

### Concrete example with `seq_length=60`:

**Frame 1 (video just started):**
- Reservoir produces state₁
- `state_window = [state₁]` (1 state)
- Aggregation uses just this 1 state → prediction is noisy/unreliable

**Frame 30:**
- Reservoir has been running autoregressively, produces state₃₀
- `state_window = [state₁, state₂, ..., state₃₀]` (30 states)
- Aggregation uses 30 states → prediction stabilizing

**Frame 60:**
- `state_window = [state₁, ..., state₆₀]` (60 states) — **window is now full**
- Aggregation uses exactly 60 states — **this matches training exactly**

**Frame 61 (window starts sliding):**
- state₁ **falls off** the deque
- `state_window = [state₂, state₃, ..., state₆₁]` (60 states)
- The aggregation no longer sees state₁

**Frame 100:**
- `state_window = [state₄₁, state₄₂, ..., state₁₀₀]` (60 states)
- Only the **most recent 60 frames** contribute to aggregation
- Frames 1-40 are completely gone from the aggregation

| | Before (unbounded) | Now (sliding window) |

| Frame 100 | Aggregates states 1→100 | Aggregates states 41→100 |
| Feature distribution | Drifts as history grows | Stays close to training distribution |
| Action sensitivity | Old action dominates forever | Old action falls off after 60 frames |

## The Root Cause

**Aggregation destroys periodicity.** The 4 stats `[first, last, mean, max]` cannot distinguish a constant signal (stationary) from a periodic oscillation (spinning) because:

- `mean` of a periodic signal = its DC component ≈ stationary equilibrium
- `first` is always ≈ 0 (cold start)
- `last` is phase-dependent (unreliable)
- `max` has only weak signal (small rotation amplitude in state space)

## Recommended Plan (ordered by impact)

### 1. Add `std` to aggregation (HIGHEST IMPACT — trivial change)

```python
c_std = c_states.std(dim=1)  # stationary: ≈0, spinning: >0

This directly measures temporal variation — the defining difference. Change `feature_dim` from `4 * res_size` to `5 * res_size`.

### 2. Add temporal diff mean (HIGH IMPACT)

```python
c_diff = (c_states[:, 1:, :] - c_states[:, :-1, :]).abs().mean(dim=1)

Captures rate of change. Stationary → 0, spinning > 0, moving >> 0. Feature dim → `6 * res_size`.

## Why Deep Reservoir is Architecturally Interesting

The current single-layer reservoir tries to do two things at once:
1. **Represent what's on screen** (position, digit identity)
2. **Detect how it's changing** (motion, rotation, stillness)

These are fundamentally different computations. Layer 1 is good at #1 but bad at #2 because α-forgetting blurs temporal changes. A second layer that specifically processes *how Layer 1's states change over time* separates these concerns.

## Deep Reservoir Architecture Design

                ↓
           s_t (1000-dim state at time t)
                ↓

                ↓

                ↓
        Aggregate both layers → Readout → 3 classes
```

The key insight: **Δs_t is near-zero for stationary and oscillating for spinning**. Layer 2's input already encodes the distinction. Layer 2's recurrent dynamics can then capture *patterns in those changes* — periodicity (spinning), monotonicity (moving), flatness (stationary).
