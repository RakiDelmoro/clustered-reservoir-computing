## 1. Echo State Network (ESN)

**Core Idea:** Random, sparse recurrent reservoir + linear readout training only

**Seminal Papers:**
- **Jaeger, H. (2001).** "The 'echo state' approach to analysing and training recurrent neural networks" — *Original ESN paper*
- **Jaeger, H. (2002).** "Adaptive nonlinear system identification with echo state networks" — *Technical report with algorithms*

**How it works:**
- Random recurrent weight matrix W (N×N, sparse ~1-10% connectivity)
- Spectral radius ρ(W) < 1.0 for "echo state property" ( fading memory)
- Only output weights W_out trained via ridge regression
- Leaky integration: x(t+1) = tanh(W_in·u(t+1) + W·x(t) + W_back·y(t))

**Pros for your research:**
- Fast training (linear regression)
- Rich temporal dynamics capture
- Well-understood theory (echo state property, memory capacity)
- Easy to implement for moving MNIST digit trajectories

**Cons:**
- Hyperparameter tuning required (spectral radius, input scaling, reservoir size)
- Fixed random reservoir may not be optimal for your specific task
- No online weight adaptation (except output layer)

**When to use:** Baseline, quick prototyping, well-understood dynamics

# 🔄 **Self-Supervised Pre-training for Reservoir World Model**

## **Core Idea: Pre-train Readout on Pretext Tasks, Freeze Reservoir**

Since reservoir weights are fixed random, "self-supervised training" means:
1. **Run reservoir** on massive unlabeled moving digit sequences
2. **Collect reservoir states** `X` (no gradient through reservoir)
3. **Train readout layer(s)** to solve pretext tasks via linear regression
4. **Freeze reservoir + pre-trained readout**, then add task-specific head (or reuse)

This gives you **rich temporal features** without costly backprop through recurrent weights.

---

## **🎯 Proposed Self-Supervised Objectives (Pretext Tasks)**

### **Pretext Task 1: Future Frame Prediction (Autoencoder-style)**
**Objective:** Predict frame t+k given frames 1...t
- **Input:** Reservoir states from `x(1)...x(t)`
- **Target:** Flattened frame `I_{t+k}` (k=1,2,3 steps ahead)
- **Readout:** `W_pred ∈ ℝ^{784×N}`
- **Loss:** MSE between predicted and actual next frames
- **Why:** Forces reservoir to encode dynamics needed for world model

### **Pretext Task 2: Temporal Order Verification (Temporal Shuffle)**
**Objective:** Given two frame windows, predict which came first
- **Sample:** Two windows: `[I_t, I_{t+Δ}]` and `[I_t, I_{t-Δ}]` (Δ=2-5 frames)
- **Input:** Concatenated reservoir states `[x(t), x(t+Δ)]` vs `[x(t), x(t-Δ)]`
- **Target:** Binary label: 1 if first window in correct temporal order, 0 if shuffled
- **Readout:** `W_order ∈ ℝ^{1×2N}` (takes concatenated states)
- **Loss:** Binary cross-entropy
- **Why:** Forces reservoir to encode arrow of time, causal structure

### **1. Input Processing**
```
Frame I_t (28×28) 
    ↓ Flatten (784)
    ↓ Random Projection R ∈ ℝ^D×784 (fixed)
u(t) ∈ ℝ^D (D=128)  ← Spatial encoder output

### **2. Structured Reservoir (Core Innovation)**
```
Reservoir state update:
x(t+1) = tanh( 
    W_in · u(t+1) +           # Input weights (random, sparse)
    W_res · x(t) +            # Recurrent weights (structured clusters)
    W_back · y(t) (optional)  # Feedback (usually 0)
)

Where W_res is NOT random Erdős–Rényi:
- Neurons partitioned into C clusters (e.g., 10 clusters × 100 neurons)
- Within each cluster: dense connectivity (p=0.3)
- Between clusters: sparse long-range connections (p=0.02)
- Each cluster has own spectral radius ρ_c:
  - Fast cluster (α≈0.3): ρ=0.8
  - Medium cluster (α≈0.6): ρ=0.9
  - Slow cluster (α≈0.9): ρ=0.95
```

### **3. Input Routing Strategy**
```
u(t) split into feature streams:
u = [u_pos; u_vel; u_rot; u_shape]  # Concatenated

Each stream connects to specific cluster groups:
- u_pos → Clusters 1-3 (position tracking)
- u_vel → Clusters 4-6 (motion dynamics)
- u_rot → Clusters 7-8 (rotation sensing)
- u_shape → Clusters 9-10 (digit identity)
```

### **4. Readout Heads (Linear)**
```
Head 1 (World Model): W_pred ∈ ℝ^{784×N}
    ŷ_pred = W_pred · x_agg(t)
    Where x_agg(t) = [x(t-2), x(t-1), x(t)]  # Temporal context

Head 2 (Action Classifier): W_action ∈ ℝ^{4×N}
    ŷ_action = softmax(W_action · mean_pool(x(t)))

Head 3 (Memory Consistency - optional): W_dyn ∈ ℝ^{N×N}
    x̂(t+1) = W_dyn · x(t)
```

## **What is Reservoir State X?**

**Definition:** `X` is the **hidden state vector** of the Clustered Reservoir at each timestep. It's a 1000-dimensional vector that encodes the reservoir's internal memory of the input sequence up to that point.

---

### **Mathematical Meaning**

The reservoir is a dynamical system:

```
State update: x_{t+1} = (1 - α) ⊙ x_t + α ⊙ tanh( W_in·u_t + W_res·x_t + b )
```

Where:
- `x_t ∈ R^1000` — **the state at time t** (this is X)
- `u_t ∈ R^128` — encoded input frame at time t
- `α ∈ R^1000` — neuron-specific leaking rates
- `W_res ∈ R^{1000×1000}` — fixed recurrent weights
- `W_in ∈ R^{1000×128}` — fixed input weights

**The state `x_t` is a compressed, fading memory of the entire past sequence** (frames u_0, u_1, ..., u_t). Different neurons have different memory timescales (fast/medium/slow).

## **1. Centroid Trajectory Readout (Low-Level Dynamics)**

### **What it predicts**
The **future 2D position** (x, y) of the digit's **center of mass** at the next timestep (or multiple future timesteps).

### **Mathematical definition**

Given:
- Reservoir state at time t: `x_t ∈ R^1000`
- Current frame at time t: `I_t ∈ {0,1}^{64×64}` (binary digit mask)

Compute:
- **Current centroid**: `(c_x(t), c_y(t))` = weighted average of pixel coordinates where `I_t > 0`
  ```
  c_x(t) = Σ_{i,j} I_t[i,j] * j / Σ_{i,j} I_t[i,j]
  c_y(t) = Σ_{i,j} I_t[i,j] * i / Σ_{i,j} I_t[i,j]
  ```
- **Target**: `(c_x(t+1), c_y(t+1))` — centroid in the next frame

**Model:** Linear mapping: `[c_x(t+1), c_y(t+1)] = W · x_t + b`

### **Label format**
- **Single-step prediction**: `[batch×T, 2]` → predict next centroid from each state
- **Multi-step**: `[batch×T, 2·H]` → predict centroids for next H steps (H=5, 10, etc.)

### **What it captures**
- **Velocity dynamics**: How fast and in which direction the digit moves
- **Bounce behavior**: Near walls, centroid velocity reverses (implicitly learned)
- **Rotation effect**: Spinning causes slight centroid wobble if digit is asymmetric
- **Collision**: Two digits → ambiguous centroid (averaged position); may need modification

### **Pros**
- Dense, continuous, low-dimensional (only 2 numbers per frame)
- Directly relates to physical motion (translation)
- Easy to train, smooth loss surface

### **Cons**
- **Loses multi-digit info**: With 2 digits, one scalar centroid is ambiguous
- **No orientation**: Centroid doesn't capture rotation
- **No shape**: Different digits with same centroid look identical

### **Implementation note**
For collision sequences (2 digits), you'd need either:
- **Two-centroid version**: Predict 4 values (x₁,y₁,x₂,y₂) — requires known ordering
- **Separate per-digit**: Use segmentation mask first to isolate each digit's centroid
